# THEOL 双版本官网与书签轻量版设计

**日期：** 2026-09-12  
**状态：** 已批准  
**目标仓库：** `https://github.com/vg188/THEOL-downloader`  
**目标官网：** `https://vg188.github.io/THEOL-downloader/`

## 1. 背景与目标

当前“北化课件助手”是 Manifest V3 Chrome 扩展，依赖 `chrome.scripting`、`chrome.downloads`、`chrome.storage.session` 和后台 Service Worker。它已提供当前 THEOL 课件目录扫描、搜索、筛选、选择、原文件下载、后台双槽队列、下载记录及失败重试。

本阶段增加一个简单的公开官网，并提供两个清晰分开的使用入口：

1. **书签轻量版：** 用户把按钮拖到书签栏，在 THEOL 课程资源页点击后打开页面内悬浮面板；选中文件总量不超过 500 MB 时在本机浏览器内打成一个 ZIP，超过 500 MB 时经二次确认后逐个下载。
2. **Chrome 完整版：** 官网按钮跳转到 Chrome Web Store 的不公开（Unlisted）条目，由用户在商店确认权限后安装。审核完成前按钮显示“Chrome 商店审核中”，不可伪装为已经可安装。

网站和书签版都不上传课件、文件名、Cookie、账号信息或课程页面内容。产品保持“非学校官方、本地运行、不能绕过平台权限”的边界。

## 2. 成功标准

- GitHub Pages 首页在桌面和移动浏览器中清晰展示两个版本及差异。
- 桌面 Chrome 用户能把轻量版按钮拖入书签栏，也能复制书签代码作为备用安装方法。
- 书签只在 `https://course.buct.edu.cn/` 页面启动，并能扫描当前已加载目录中的 PDF、PPT、PPTX。
- 所选文件的全部大小已知且总计不超过 **500 MB（500 × 1024 × 1024 字节）**时，用户确认后只产生一个 ZIP 下载。
- 总量超过 500 MB，或任何所选文件大小未知时，不创建 ZIP；先显示文件数、已知/估算大小和多文件下载提示，用户再次确认后才逐个下载。
- 完整版按钮可通过单一配置从“审核中”切换到 Chrome Web Store 不公开详情页。
- 发布产物不包含浏览器配置、身份凭据、真实课程数据或下载的课件。

## 3. 不在本阶段范围

- 不用书签版替代或删除现有 Chrome 扩展。
- 不从普通网页静默安装 Chrome 扩展，也不绕过 Chrome Web Store 的用户确认。
- 不建设后端、数据库、账号系统、遥测、更新服务或课件中转服务。
- 不支持递归目录、自动翻页、跨课程扫描或绕过登录/访问权限。
- 不承诺书签版在页面关闭、刷新、跳转或登录失效后继续任务。
- 不在首发中提供 Firefox、Edge 商店、Tampermonkey 或移动浏览器版本。
- 不在本阶段自动创建 Chrome Web Store 开发者账号或代替用户完成商店中的身份、付费和隐私声明操作。

## 4. 发行与安装模型

### 4.1 官网

代码仓库为公开仓库 `vg188/THEOL-downloader`，GitHub Pages 使用项目站点路径：

```text
https://vg188.github.io/THEOL-downloader/
```

首次发布时官网可先上线书签版。完整版卡片处于审核中状态。Chrome Web Store 审核通过后，把构建配置中的 `chromeWebStoreUrl` 设置为实际不公开条目 URL并重新部署；官网主按钮随之变为“添加至 Chrome”。

### 4.2 完整版

Chrome 已禁止普通网站内联安装扩展，因此官网不能实现真正的静默一键安装。合规流程为：

```text
官网“添加至 Chrome” → Chrome Web Store 不公开详情页 → 用户查看权限并确认安装
```

不公开条目不能由商店搜索发现，但拥有链接的用户可以访问。开发阶段继续保留 ZIP/“加载已解压的扩展程序”流程，但它放在面向开发者的折叠说明或仓库 README 中，不作为普通用户主入口，也不分发自托管 CRX。

### 4.3 书签轻量版

官网展示可拖拽的锚点按钮，其 `href` 是压缩后的 `javascript:` 启动器。按钮同时支持“复制书签代码”，用于浏览器或页面环境无法直接拖动时手工新建书签。

启动器只承担以下职责：

1. 验证当前页面协议和主机；非 `https://course.buct.edu.cn/` 时显示简短提示并停止。
2. 检测同一版本是否已加载；已加载时仅重新显示现有面板，不重复注入。
3. 从当前 GitHub Pages 项目下的**版本化固定路径**加载轻量版程序，例如 `/THEOL-downloader/bookmarklet/v1/bookmarklet.js`。
4. 外部脚本加载失败或超时时，用启动器内置的提示说明可能是 CSP、校园网络或 GitHub Pages 不可达，并引导改用完整插件。

固定路径由发布流程维护；已有书签不因站点重新构建而失效。破坏兼容性的更新发布为新的主版本路径和新的书签启动器。

## 5. 实施前可行性门禁

远程启动器方案存在一个不能仅靠设计推断的风险：THEOL 顶层页或其 frame 的 Content Security Policy 可能阻止从 GitHub Pages 注入脚本，也可能阻止 Blob Worker。正式实现前必须先制作不含扫描和下载逻辑的最小探针，并由用户在已登录的真实课程页主动点击测试：

1. 书签内联代码能执行并显示可见标记；
2. 能从 `https://vg188.github.io/THEOL-downloader/` 加载固定测试脚本；
3. 远程脚本能访问目标同源 frame；
4. 能发起一个不下载正文的同源元数据请求；
5. 若归档设计依赖 Worker，能创建本站脚本或 Blob Worker。

探针不得读取真实课件正文、触发下载或收集页面数据。通过标准是上述 1–4 全部成功；第 5 项失败时改为主线程分块归档并在 UI 中降低刷新频率。若远程脚本加载失败，则方案 A 不进入完整开发，改用以下降级决策：优先评估构建后尺寸可控的自包含书签；仍不可接受时，把轻量版改为可复制的 DevTools/用户脚本方案，官网明确说明安装差异，并重新请用户批准。不能把“弹出错误并引导完整版”当作轻量版已经交付。

## 6. 官网信息架构与视觉

官网为无框架静态单页，延续插件的白底、深色文字、红色强调色和克制中文文案，不做自动播放视频、复杂视差或营销型动画。

页面按以下顺序组织：

1. **首屏：** 产品名、用途、非官方说明，以及“拖到书签栏”和完整版状态按钮。
2. **版本对比：** 用表格说明轻量版与完整版在安装、ZIP、后台队列、关闭面板后继续、下载记录和适用场景上的差异。
3. **轻量版安装三步：** 显示书签栏、拖入按钮、在 THEOL 当前课件目录点击；附复制代码备用操作。
4. **使用及 500 MB 规则：** 说明 ZIP 与逐项下载的分流、二次确认、多文件下载权限和页面需保持打开。
5. **隐私与权限：** 不上传、不读取密码、不导出 Cookie、只处理当前目录、源码公开。
6. **常见问题：** 启动失败、GitHub Pages 被阻止、登录失效、多个文件下载被拦截、大小未知和完整插件安装。
7. **页脚：** 源码、问题反馈、版本、更新时间及“非北京化工大学官方产品”。

可拖拽书签必须是真实链接，而不是仅响应点击的按钮；键盘用户可聚焦并使用“复制代码”。触控设备不承诺拖拽安装，显示“书签轻量版需要桌面浏览器”。页面遵循可见焦点、语义标题、足够对比度和 `prefers-reduced-motion`。

## 7. 书签版架构

### 7.1 模块边界

建议新增源码结构：

```text
site/
  index.html
  site.css
  site.js
  assets/
src/bookmarklet/
  bootstrap.js
  main.js
  scanner.js
  view.js
  download.js
  archive.js
  worker.js
```

构建产物：

```text
dist/site/
  index.html
  assets/
  bookmarklet/v1/bookmarklet.js
  bookmarklet/v1/archive-worker.js
```

- `bootstrap.js` 生成最小启动器，不包含业务实现。
- `main.js` 负责生命周期、单实例控制和状态协调。
- `scanner.js` 复用/适配现有纯解析与 URL 策略，只遍历当前顶层页面可访问的同源 frame。
- `view.js` 在固定的宿主节点下创建 Shadow DOM 悬浮面板。
- `download.js` 负责带当前登录状态的同源读取、内容验证和逐项下载。
- `archive.js` 协调 ZIP 任务、进度、取消和失败清单。
- `worker.js` 在 Web Worker 中执行 ZIP 存储封装，减少主线程卡顿；ZIP 实现打入本站产物，不从第三方 CDN 动态加载。

现有扩展和书签版共享的解析、格式签名、URL 校验和安全文件名逻辑应提取成无 `chrome.*` 依赖的模块；扩展专属队列和 API 桥保持独立，避免为复用而削弱权限边界。

### 7.2 页面与 frame

启动器仅接受精确主机 `course.buct.edu.cn` 和 HTTPS。程序从顶层文档开始，递归访问同源且当前已加载的 frame；遇到不可访问 frame 时跳过并在扫描结果中给出原因。它不修改平台原始下载按钮，不猜测其他资源 ID，不跟随到其他课程或目录。

每次扫描生成不可复用的扫描代次。目录位置、frame 文档或资源标识发生变化后，旧选择失效，用户必须重新扫描。扫描初始不自动勾选任何文件。

### 7.3 悬浮面板

Shadow DOM 面板提供：课程名、扫描按钮、搜索、PDF/PPT/PPTX 筛选、全选当前结果、文件名/格式/大小、选择计数、进度、取消、关闭和下载操作。关闭面板只隐藏 UI；未开始任务时可重新打开，进行中的任务则把“关闭”改为“隐藏”，并明确页面不能刷新或关闭。

面板不使用平台 DOM 的 CSS 类名，最高层级控制在局部宿主节点；不阻止课程页正常滚动和键盘操作。发生致命加载错误时，启动器使用原生 `alert` 作为最后的可见反馈，因为完整面板可能尚未加载。

## 8. 500 MB 分流与下载状态机

### 8.1 决策规则

对当前选择计算 `knownTotalBytes`，并记录是否存在未知大小：

```text
所有大小已知 且 knownTotalBytes <= 524,288,000 → ZIP 候选
knownTotalBytes > 524,288,000                   → 逐项下载候选
存在任何未知大小                              → 逐项下载候选
```

不为了判断未知大小而预先完整读取文件。界面必须把“平台报告大小”称为预计值；下载时响应实际大小可能不同。

### 8.2 ZIP 分支

ZIP 分支在首次点击后显示：文件数、预计总大小、内存风险、必须保持页面打开以及“确认打包”。用户确认后：

1. 按顺序以 `credentials: 'include'` 读取已验证的同源下载 URL。
2. 延续完整版的 MIME、登录页/错误 HTML 和 PDF/PPT/PPTX 文件头检查。
3. 每个响应按块交给归档 Worker，ZIP 条目使用经过安全处理的原始文件名。
4. 使用 ZIP Store 模式，不对通常已压缩的课件再次做 Deflate。
5. 显示当前文件、文件进度、总进度、成功数和失败数，并提供取消。
6. 完成后生成一个 Blob URL，触发一次用户可见下载，然后撤销 URL 并释放引用。

500 MB 是进入 ZIP 的最大**预计原文件总量**，不是浏览器内存保证。确认框明确提示低内存设备仍可能失败。若响应头或已读取字节表明实际累计内容将超过 500 MB，程序立即停止继续归档、取消尚未完成的请求、销毁未发布的临时 ZIP，且**不会自动改为逐项下载**。它返回选择确认界面，说明实际大小超限；只有用户再次确认后才逐个下载，避免重复请求或意外批量下载。

单个文件失败时继续处理其余文件。至少一个文件成功时，ZIP 中加入成功文件；若有失败，再加入 UTF-8 的 `下载失败清单.txt`，每行包含安全文件名和用户可理解的失败原因。全部失败时不生成空 ZIP。

### 8.3 逐项下载分支

超过 500 MB 或大小未知时，首次点击只打开确认界面，显示：

- 所选文件数量；
- 已知总量及未知大小文件数量，或超过 500 MB 的预计总量；
- “不会生成 ZIP，将逐个下载原文件”；
- Chrome 可能要求允许该站点自动下载多个文件；
- 页面必须保持打开，失败项不会由后台恢复。

用户点击“确认逐个下载”后，程序串行创建带 `download` 属性的同源链接并触发下载，文件之间留出短暂调度间隔，避免同一事件循环内突发触发。浏览器仍有权阻止多文件下载；程序不尝试绕过该策略。面板显示已触发数量，但不把“已触发”误报成“已保存完成”，因为书签脚本无法读取 `chrome.downloads` 的最终状态。

用户取消、页面跳转或刷新即结束书签任务。任何情况下只允许一个活动下载/归档任务。

## 9. 安全、隐私与供应链

- 只接受 `https://course.buct.edu.cn/*`，拒绝 HTTP、其他主机、带用户名密码的 URL、重复关键 ID、编码绕过和不符合平台模式的下载路径。
- 所有课程请求使用页面现有会话；代码不读取、记录、上传或展示 Cookie 值及密码。
- GitHub Pages 只响应静态站点和程序文件，不接收课件数据。首发不加入分析脚本、广告、错误上报 SDK 或第三方 CDN。
- ZIP 库必须锁定确切版本并随构建产物打包；发布文档记录许可证。依赖代码不从运行时网络动态更新。
- 书签启动器的远程代码能力在官网明确说明，并链接公开源码、版本和更新时间。
- 严格限制远程加载 URL 为项目自有 GitHub Pages HTTPS 固定版本路径；不接受查询参数指定任意脚本地址。
- GitHub Actions 使用最小权限：构建 job 默认只读仓库，部署 job 仅授予 Pages 所需的 `pages: write` 与 `id-token: write`。
- Actions 和发布包不读取用户本地环境变量中的 GitHub token；本地 `gh` 凭据不写入仓库。

## 10. Chrome Web Store 不公开发布

完整版沿用 Manifest V3，提交前准备：

- 商店名称、简短说明、详细说明、图标和截图；
- 单一用途说明；
- `scripting`、`downloads`、`storage` 和 `https://course.buct.edu.cn/*` 的逐项权限理由；
- 隐私政策页面（由 GitHub Pages 托管）；
- 数据使用声明：不收集、不出售、不上传用户数据；
- 支持链接和公开源码链接；
- 经验证的 ZIP 发布包。

商店可见性选择 **Unlisted**。审核通过后只在官网配置商店详情 URL，不把扩展 ID硬编码进书签业务代码。用户始终在 Chrome Web Store 页面完成权限确认。

## 11. 构建与 GitHub Pages 部署

现有扩展构建和 ZIP 白名单保持不变，新增独立站点构建命令。建议脚本语义：

```text
npm run test             # 现有核心测试
npm run test:browser     # 现有原生扩展回归
npm run test:bookmarklet # 书签扫描、分流、ZIP 和安全测试
npm run test:site        # 官网交互与链接状态测试
npm run build            # 构建扩展
npm run build:site       # 构建 dist/site
npm run package          # 打包扩展 ZIP
```

`.github/workflows/pages.yml` 在默认分支更新时执行安装、全部无账号自动化测试和 `build:site`，再上传 `dist/site` 为 Pages artifact。测试夹具只模拟 THEOL 页面和文件，不访问真实学校资源，也不需要学校账号。

部署前创建公开仓库 `vg188/THEOL-downloader`，将本地仓库添加为远程，并在 GitHub 仓库设置中把 Pages Source 设为 GitHub Actions。创建仓库、推送、启用 Pages 均属于对远程状态的修改，只在实施阶段明确执行；不把现有工作直接强推覆盖远程内容。

## 12. 测试与验收

### 12.1 自动化

- 启动器：正确域名加载、错误域名拒绝、重复点击单实例、加载失败提示、固定版本 URL。
- 扫描：嵌套同源 frame、当前目录边界、无后缀元数据、GBK、重复项、坏 URL、登录页和错误 HTML。
- 选择：默认不选、搜索/筛选保留选择、目录变化使旧选择失效。
- 分流：恰好 500 MB 进入 ZIP；500 MB + 1 字节进入逐项；任一未知大小进入逐项；实际累计超限必须回到二次确认且不自动下载。
- ZIP：文件名、Store 模式、内容字节、失败清单、全失败不下载、取消释放资源、只触发一个下载。
- 逐项：第一次点击不下载、第二次确认后串行触发、取消停止、状态只写“已触发”而非“已完成”。
- 网络边界：断言课程内容只请求 `course.buct.edu.cn` 模拟源；除加载自有版本化程序外无外发请求。
- 官网：拖拽链接是有效 `javascript:` URL、复制备用、审核中/商店链接两种状态、键盘、移动提示、无 JavaScript 时仍有完整说明。
- 现有扩展：69 项核心测试及 4 项原生弹窗布局测试继续通过。

### 12.2 人工验收

- Chrome 桌面版显示书签栏后，可从官网拖动并在模拟 THEOL 页启动。
- CSP/网络阻止远程程序时能看到明确失败提示和完整版入口。
- 选择小型模拟文件可得到单个 ZIP，解压后的文件逐字节等于夹具响应。
- 选择超过 500 MB 的模拟元数据时，在第二次确认前没有下载；确认后浏览器若拦截多文件，说明与实际提示一致。
- 官网 360px、768px 和桌面宽度无横向溢出；可见焦点、对比度和减少动态效果通过检查。
- GitHub Pages 的最终 URL、静态资源、版本化书签脚本、隐私页和源码链接可从无登录窗口访问。

真实课程验收必须由用户在自己的已登录测试浏览器中主动进行，先选少量有权访问的文件；不自动批量读取整门课程，也不在测试报告中把模拟数据描述为真实下载结果。

## 13. 文档与用户文案

README 和官网必须清楚区分：

- **轻量版：** 拖书签、页面内运行、≤500 MB 可 ZIP、页面必须保持打开、无后台完成状态。
- **完整版：** Chrome Web Store 安装、后台队列、Chrome 下载记录、适合大量或长期使用。
- “添加至 Chrome”仅在商店 URL 已配置时使用；审核中不得链接到假地址。
- “下载已触发”不等于“下载已完成”。
- 文件头检查不是完整性证明或安全扫描。
- 两种版本都不能绕过学校权限、登录状态、校园网络或浏览器策略。
