# 北化课件下载助手：首版设计

日期：2026-09-11
状态：功能范围及本文均已获用户确认，进入实现。

## 1. 用户目标与使用方式

在已登录的北京化工大学教学平台中，打开课程资源列表，点击 Chrome 扩展，勾选 PDF、PPT、PPTX，一次提交下载。扩展获取平台提供的原始文件，不把预览图片转换成文件。

典型流程：进入课程资源目录 → 点击扩展 → 扫描当前列表 → 搜索或勾选文件 → 下载所选 → 查看结果，必要时重试失败项。

首版只处理当前目录已经加载的资源列表，不自动进入子目录、不自动翻页、不跨课程扫描。用户切换目录或页码后可以重新扫描。

## 2. 已确认的平台结构

已通过用户手动登录的 Chrome 检查真实课程资源列表和一份 PPT 预览页，没有批量下载文件。

- 课程主页包含课程资源 iframe，资源页又包含目录 frame 和文件列表 frame。
- 文件列表使用 `/meol/common/script/listview.jsp`，课程和目录分别由 `lid`、`folderid` 标识。
- 列表中的资源名称不一定带扩展名，不能只查找以 `.pdf` 或 `.ppt` 结尾的链接。
- 文件入口使用 `/meol/common/script/preview/download_preview.jsp`，携带 `fileid`、`resid`、`lid`。
- 已检查的预览页在标题区域展示原始文件名、大小和“下载”链接。
- 已检查的原文件下载入口为 `/meol/common/script/download.jsp`，同样携带 `fileid`、`resid`、`lid`。

这些是已观察到的页面结构，不代表所有课程都已验证。解析器必须处理结构不匹配的情况，而不是猜测其他资源 ID 或拼造缺失的下载链接。

## 3. 界面与交互

扩展使用中文弹出面板，顶部显示课程名称、扫描范围和“重新扫描”。主体是文件列表，底部是所选数量和“下载所选”按钮。

### 扫描与筛选

- 用户点击扫描后，识别当前课程标签页内实际加载的资源列表，包括同源嵌套 frame。
- 如果当前标签页不是学校平台，显示“请先打开学校教学平台的课程资源页”。
- 如果尚未进入资源列表，提示用户打开课程资源；不代替用户遍历其他栏目。
- 扫描列表中出现的预览链接，去重后读取预览页的文件名、大小和下载入口。
- 元数据请求最多同时进行 3 个，每个请求超时为 15 秒；单个失败不阻断其余文件。
- PDF、PPT、PPTX 按扩展名识别，不区分大小写。其他文件不进入可下载列表，并显示跳过数量。
- 文件大小沿用平台展示值；没有大小时显示“大小未知”，不虚构精确字节数。
- 初次扫描完成时不默认勾选任何文件。支持按文件名搜索、按格式筛选、逐项勾选和全选当前筛选结果。
- 切换筛选条件不会静默清空已选项；底部始终显示全部已选数量。
- 切换目录、课程或重新扫描后清空旧选择，避免把旧列表误认为当前列表。已提交的下载任务不受影响。
- 没有文件、扫描进行中、部分识别失败、登录失效、无下载权限等状态都有明确提示。

### 下载与重试

- 仅“下载所选”会创建下载任务。扫描和勾选均不会下载原文件。
- 下载最多同时进行 2 个；其余排队，避免同时向平台发起大量请求。
- 文件显示“排队中”“下载中”“已完成”“失败”状态；有可靠总大小时显示进度，否则只显示下载状态。
- 关闭弹出面板不终止已提交队列；再次打开可以查看本次浏览器会话内的任务。
- 重复点击不会重复提交同一项正在排队或下载的文件。需要再次下载已完成文件时，用户必须明确再次选择提交。
- 失败项由用户点击重试，不无限自动重试；重试前重新确认该资源的可用下载入口。
- 登录过期、资源无权限、网络中断和用户在 Chrome 中取消下载分别给出可理解的原因。

## 4. 保存规则

使用 Chrome 原生下载管理器。保存位置是 Chrome 配置的下载根目录下的“课程名/原始文件名”，默认对应系统的“下载”目录。

- 保留原文件名和扩展名，只替换 Windows 不允许的字符、路径分隔符及控制字符；拒绝路径穿越、绝对路径和保留设备名。
- 无法可靠识别课程名称时使用“课件”作为文件夹名。
- 同名文件由 Chrome 自动追加编号，不覆盖已有文件。
- 不合并、不转格式、不打包 ZIP。
- Chrome 的“每次下载前询问保存位置”、安全检查或学校管理策略仍然有效；扩展不承诺绕过这些确认。
- 浏览器重启后，已交给 Chrome 的任务由 Chrome 管理；首版不自动恢复尚未提交给 Chrome 的排队项。

## 5. 技术结构与边界

采用 Chrome Manifest V3。运行时使用原生 JavaScript、HTML、CSS 和 Chrome 扩展 API，不引入运行时第三方库；允许使用开发和测试工具。

| 模块 | 职责 | 不负责的内容 |
| --- | --- | --- |
| 弹出面板 | 筛选、选择、扫描进度、下载任务展示 | 不持有唯一队列，不直接解析平台业务页面 |
| 页面扫描器 | 按需读取已加载列表、课程上下文和预览页；使用 DOM 解析文件元数据 | 不遍历其他课程，不读取账号信息，不下载原文件 |
| 平台解析与校验 | 解析资源链接、原始文件名、格式和下载入口；规范化标识和文件路径 | 不执行页面脚本，不构造不存在的资源 |
| 后台服务 | 验证消息、维护下载队列、调用原生下载 API、汇总状态 | 不依赖弹出面板持续打开，不解析 DOM |

后台使用浏览器会话存储保存队列状态，并在服务工作线程恢复时与 Chrome 下载记录校对，不能只依靠内存数组或长期计时器。

扩展权限固定为 `scripting`、`downloads`、`storage`，站点权限仅为 `https://course.buct.edu.cn/*`。通过用户点击扩展后的按需注入读取页面，不常驻扫描所有打开的页面；不得申请所有网站访问、密码管理、调试器或读取 Cookie 的权限。

只接受来自扩展自身界面或学校站点内容脚本的消息。对课程和文件标识、消息类型、下载 URL、文件名及任务 ID 做独立校验；页面内容不视为可信指令。

## 6. 登录、安全与数据

- 仅适配 `https://course.buct.edu.cn/`。如发现资源跳转到其他域名，显示暂不支持，不自动扩大访问权限。
- 使用浏览器已有登录状态发起同源请求，不读取、复制或保存 Cookie，不收集账号密码，不访问登录表单字段。
- 只读取列表中已经出现、当前账号能访问且有正常下载入口的资源；无下载按钮或权限不足时跳过并说明原因。
- 不执行预览页脚本，不使用 `eval` 解析网页，不把来自网页的文件名或错误内容作为 HTML 插入扩展界面。
- 登录页或错误页不能被标记为成功下载的课件。无法可靠识别资源时，提示重新登录或重新扫描，而不是把 HTML 当成 PPT/PDF。
- 不添加遥测或远程服务器；不上传课件、文件名、登录状态或下载记录。
- 会话内仅保存必要的文件元数据和任务状态；不导出身份认证信息。
- 本地浏览器调试记录不进入 Git，也不进入扩展发布包。测试样例去除姓名、学号、Cookie 和会话令牌。

## 7. 为什么选择专用扩展

通用网页链接下载器实现简单，但会漏掉多层 frame 中的文件，也无法从没有后缀的列表名称可靠判断格式。

THEOL 专用扩展需要维护页面适配，但可以读取原文件名和平台真实下载入口，并提供独立于弹出面板的下载队列。因此选择专用扩展，不采用通用链接扫描方案。

代价是学校改版后可能需要更新解析器；页面结构不匹配时应明确报错，不静默猜测链接。

## 8. 验收与交付

### 自动化验证

- 资源列表及预览页解析覆盖：嵌套页面、无后缀标题、PDF/PPT/PPTX、重复链接、非课件文件、中文名、大小缺失、缺少下载入口。
- 安全校验覆盖：站外链接、危险 URL 协议、非法标识、Windows 文件名、路径穿越、页面文本注入、登录页和错误页。
- 队列覆盖：并发上限、重复点击、失败重试、弹出面板关闭、后台恢复、用户取消。
- 界面覆盖：键盘选择、搜索筛选、全选语义、无文件、部分扫描失败和未登录提示。

### 真实平台验证

使用用户已登录的测试浏览器加载扩展，在当前课程资源目录验证扫描结果；用少量已勾选课件验证原始格式、文件名、保存位置和状态反馈。不为了测试擅自批量下载整门课程。

安装流程和真实下载成功必须分别验证。设计审查时仅完成平台结构检查；实现后的最新结果和未验收项见 `docs/verification.md`。

### 交付物

- 可通过 Chrome“加载已解压的扩展程序”安装的扩展目录。
- 源码、自动化测试及运行方式。
