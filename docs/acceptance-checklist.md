## 0. 开始前

- [ ] Chrome 地址栏打开 `chrome://extensions`，右上角开启「开发者模式」
- [ ] 「加载已解压的扩展程序」→ 选择 **`E:\codex\File-scri\dist\extension`**（直接含 `manifest.json` 的这一层，不是它的父目录）
- [ ] 列表中出现「北化课件助手」版本 1.0.1；点拼图图标把它**固定到工具栏**
- [ ] 在同一个 Chrome 里登录 `https://course.buct.edu.cn/`

> 如果你打算用 ZIP 安装：解压后再选**解压出来的、直接含 `manifest.json` 的目录**，不要直接选 `.zip` 文件。

### 三条硬规矩

1. **每次只勾选一份**，确认对了再继续。不要批量下载整门课。
2. 扩展的下载前校验会向服务器发一次带 Range 的请求，**可能增加平台的下载计数**，属正常。
3. 遇到 Chrome 或系统的另存为、安全检查提示，按提示操作；扩展替不了你点系统对话框。

## A. 课程资源 · 当前目录（真实 PDF 与 PPTX）

这一档此前只实测过一份 PPT。需要补齐 PDF 和 PPTX。

**A1 · 真实 PDF**

- [ ] 进入某门课的「课程资源」，打开一个含 PDF 的文件夹，等列表加载完
- [ ] 点工具栏图标打开面板，点「扫描课件」
- [ ] 扫描完成后，**勾选数应为 0**（扩展不自动勾选）
- [ ] 只勾选 **1 份 PDF** → 「下载所选」
- [ ] 「下载记录」里状态依次走到 **已完成**
- [ ] 到 Chrome 下载页（`chrome://downloads`）确认这条下载存在
- [ ] 核对三件事：
  - [ ] 文件名与平台上显示的一致（中文没有乱码、没有变成 `%E4%B8%AD` 之类）
  - [ ] 扩展名是 `.pdf`
  - [ ] 大小与平台展示的大小相符
- [ ] 点「在文件夹中显示」，确认落在 **`Chrome下载目录 / 课程名 / 原始文件名`**
- [ ] 用浏览器或 PDF 阅读器**真的打开它**，确认能正常显示

**A2 · 真实 PPTX**

- [ ] 同一目录里只勾选 **1 份 PPTX** 下载
- [ ] 重复 A1 的核对项：文件名、`.pptx` 扩展名、大小、保存路径
- [ ] 用 PowerPoint 或 WPS **真的打开它**，确认不是网页或登录页伪装的

> PPT 容器此前实测：文稿流与图片流的哈希与服务器原件一致，但整个 OLE 容器有字节差异（Current User 流被本机重写），原因未定位。**内容一致即可，不必逐字节比对。**

**A3 · 扫描边界（顺手确认）**

- [ ] 列表里若有非 PDF/PPT/PPTX 的文件，应显示为「跳过」，而不是被列出来
- [ ] 搜索框输入关键词后，列表正确过滤
- [ ] 切换到「PDF」筛选后，之前勾选的其他格式文件**仍被保留**，底部显示「另有 N 份已隐藏」
- [ ] 换到别的目录后重新打开面板，旧扫描失效、勾选清空，但**下载记录保留**

## B. 单元学习 · 当前单元（Task 9 主项）

这是目前唯一的真实下载空白。**建议挑一份体积最小的课件。**

- [ ] 进入某门课的「单元学习」，打开一个单元，等列表加载完
- [ ] 打开面板：顶部应出现「扫描范围」下拉，默认值为 **当前单元**
- [ ] 面板上「只扫描当前单元」的说明可见
- [ ] 点「扫描当前单元」
- [ ] 扫描完成后勾选数为 0；只勾选 **1 份**课件 → 「下载所选」
- [ ] 「下载记录」走到 **已完成**
- [ ] 核对：文件名、扩展名、大小、保存路径（**不新增单元子文件夹**）
- [ ] 用对应软件**真的打开它**
- [ ] 面板上该文件若带有「所属单元 …」标注，确认单元名与当前单元一致

## C. 单元学习 · 全部单元（Task 9 次项）

- [ ] 仍在单元学习页面，把扫描范围切到 **全部单元**
- [ ] 点扫描按钮，**先弹出确认框**，显示将读取的单元数量
  - [ ] 这个数量与平台上你看到的单元数一致吗？一致 / 不一致（记下差多少）
  - [ ] 在你点「确认扫描」之前，确认框说明了「不会下载课件正文」
- [ ] 点「确认扫描」
- [ ] 扫描过程中「扫描范围」下拉**不可切换**
- [ ] 面板显示「正在读取单元 N / M，已发现 X 个候选」的进度
- [ ] 扫描完成后：
  - [ ] 同一课件出现在多个单元时，只列出**一项**，并显示「另见 N 个单元」
  - [ ] 若有单元读取失败，在结果**下方单独列出**，其余单元的结果照常显示
- [ ] 只勾选 **1 份**课件下载，核对文件名、扩展名、大小、保存路径、可打开性

## D. 异常与恢复（可选，但很有价值）

挑一项试试，确认失败时的表现和文档一致：

- [ ] **取消**：在 Chrome 下载页取消一个进行中的下载 → 面板应显示「失败」，并提供「重试」
- [ ] **手动重试**：点「重试」→ 任务重新排队并最终完成
- [ ] **关闭面板**：下载提交后立即关闭面板 → 下载**继续**，重新打开面板仍能看到记录
- [ ] **登录失效**（可选）：退出登录后扫描 → 应提示登录失效，而不是静默失败或下载到登录页

  - [ ] 若拖不动：点「复制书签代码」，手动新建书签、把代码粘到「网址」栏同样可用

**F2 · 课程资源目录实测**

- [ ] 登录后进入某门课的「课程资源」，一直进到右侧出现 PDF/PPT/PPTX 列表
- [ ] 点击书签栏的书签
- [ ] 页面内出现面板（不是弹窗、不是跳转）
- [ ] 点「扫描当前目录」
- [ ] 列表出现课件，勾选数初始为 0
- [ ] 只勾选 **1 份**（建议先 PDF）→ 确认下载
- [ ] 下载完成，核对：文件名、扩展名、能被对应软件打开
- [ ] **整个过程页面必须保持打开**——书签版没有后台队列，切走或刷新会中断（这正是它与插件版的核心差别）

**F3 · 500 MB 规则**

- [ ] 勾选一批总量明显小于 500 MB 的课件 → 应走「打包 ZIP」
- [ ] 若总大小超过 500 MB → 应改为逐个直接下载，而不是打包

**F3.5 · 出问题时怎么拿到诊断信息**

如果点了书签没反应、扫描不出来、或报了看不懂的错，按下面拿诊断：

1. 在 THEOL 页面上按 **F12** 打开控制台
2. 点一下书签栏的书签，让面板出现（面板没出现的话也可以直接做第 3 步）
3. 在控制台粘贴并回车：

```js
copy(__THEOL_DOWNLOADER_BOOKMARKLET_V1__.diagnose())
```

4. 结果已复制到剪贴板，直接贴给我

**这段诊断已做脱敏**：只有数量、页面路径（不含 `?` 后面的参数）、识别到的页面类型、和最后一个错误码。**不含课程名、课程 ID、资源 ID、文件名、账号信息**——这些字段在代码里就没有被采集，所以可以放心贴。

看几个关键字段就能定位：

| 字段 | 含义 |
| --- | --- |
| `stamp` | 书签版本与打包日期，与 F1 在页面上记下的那一行对照，就能确认你拖的是不是最新的 |
| `page.supported` | `false` = 当前不在学校平台页面上 |
| `page.frameCount` | 页面里可读的同源 frame 数；`0` 说明一个都读不到 |
| `page.candidates` | 识别出的列表类型；空 = 没找到课件目录或单元页 |
| `page.rejected.otherCourse` | 有可读列表但属于别的课程（课程串了） |
| `page.rejected.unrecognised` | 可读但不是课件列表的 frame 数 |
| `error.code` | `NO_DIRECTORY` = 没进到课件目录；`AMBIGUOUS_DIRECTORY` = 页面上有多个列表需要单独打开 |

**F4 · 单元学习页面（如该课有）**

- [ ] 进入「单元学习」某个单元，点书签
- [ ] 扫描范围默认应为**当前单元**

## 上线前待决：两件需要你拍板的事

读回 09-12 那条线程（`codex://threads/01a094b7-…`）后发现官网这条线有三处卡住；第 2 件（部署路径）已在 2026-09-19 解决，剩下两件验收前你最好先定夺：

### 1. 插件版分发方式：官网文案与实际决定互相矛盾

你当时明确说过**不公开**（不上架 Chrome 应用商店）、要走**打成压缩包**分发。但官网现在渲染出来的是：

```html
<span id="chrome-install" class="button" aria-disabled="true">Chrome 商店审核中</span>
```

一个**点不了的按钮**，旁边提示还写着"按钮只会打开 Chrome 应用商店的详情页"。也就是说现在访问官网的人**根本拿不到插件版**，且会以为还在审核。

要改成什么，取决于你：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A. 网页明确引导手动安装** | 按钮换成「下载 ZIP（手动安装）」，指向仓库 Release 附件；旁边写清解压→开发者模式→加载已解压扩展 | 最简单，符合"不公开"，但用户要 4 步 |
| **B. 上架 Chrome 应用商店** | 填 `site/config.json` 的 `chromeWebStoreUrl`，按钮自动变成「添加至 Chrome」 | 一键安装，但要交 5 美元开发者费 + 通过商店审核，且与你说过的"不公开"冲突 |
| **C. 保持现状** | 什么都不改 | 官网等于只有书签版一个可用入口 |

> 注意：一旦你决定 A 或 B，我也得同步 `site/index.html` 第 58–60 行和第 74 行的文案（现在还在写"经 Chrome 应用商店确认权限后安装"）。
