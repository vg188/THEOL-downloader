## 下载顺序

| 页面实际提供的内容 | 保存结果 |
| --- | --- |
| 匹配资源 ID 的原文件下载入口 | 原文件，保留原名和字节 |
| 预览页明确声明的整份原格式资源流 | 完整校验后保存原名、真实格式和原始字节，不合成图片 |
| 整份预览 PDF，包括 PDF.js 的 `file` 参数和明确的 PDF 数据字面量 | `文件名（预览版）.pdf`，直接保存响应，不重新合成 |
| 只有完整的分页图片清单 | `文件名（预览版）.pdf`，按清单顺序和原比例嵌入所有页 |
| 播放器提供的独立 MP4／其他已适配媒体文件 | 保持实际媒体扩展名，标为预览副本 |
| Word 转换后的富文本 | 离线 HTML，保留正文、表格和内嵌 PNG/JPEG |
| 纯在线文本 | UTF-8 TXT |

**整份文件优先，图片合成兜底。** `preview.jsp` 是加载入口，不能因为入口返回 HTML 就断言没有整份资源；需要继续解析 iframe 和页面明确给出的资源地址。也不能仅凭接口名字或 `Content-Type` 判断文件格式。

### PDF 名称的接口不一定返回 PDF

实际 THEOL 模板会声明 `resPdfShow.do?resId=…&lid=…`，然后尝试将查看器地址赋给 `#pdfIframe`；Office 页面即使没有这个 iframe，也可能保留这段声明。对当前课程实测，该接口将完整 PPTX／DOCX 字节标成 `application/pdf`。

工具只识别这个已观察到的模板结构和同一课件的明确地址，不从分页图片名推算路径，也不枚举 ID。只对绑定课程／资源与原文件元数据的这条来源延后 MIME 判断；必须完整核对 Office 类型、文档关系、ZIP 目录及 CRC，或旧 Office 复合存储结构。错误页、截断内容、DOCX 误配 PPTX、真正的 PDF 误配 PPTX 都会停止下载，不会靠换后缀蒙混通过。普通原文件入口和其他预览路径仍执行原有 MIME 检查。

原格式流采用 `downloadKind: original` 与 `downloadSource: preview-stream`，界面说明“保存前完整校验”。它不是生成型预览副本；只有实际通过 PDF 检查的内容才会保存成 PDF。

## 范围与失败处理

- 扫描只读取当前课程的元数据、预览包装页和内容清单，不请求原文件、图片、视频或 PDF 正文。
- 只接受学校域名和已适配路径；嵌套预览必须与当前课件标识一致。不修改权限，不试探任意下载 URL。
- 原格式流仅在用户选择下载后完整读取；书签和扩展复用这一次验证过的字节，不再另发一次未经完整校验的原生请求。逐个下载最多读取 200 MiB；ZIP 遵守用户设置的剩余打包预算。
- 扩展用本机隐藏的 `offscreen` 文档持有准备任务与 Blob。生成和完整读取串行处理，关闭面板或后台 Worker 重启会复用同一任务；结束后释放 Blob。二进制内容不写入队列存储或发给第三方。
- ZIP、逐个下载和扩展共享身份与格式校验。转换副本使用真实输出扩展名，不套用原 PPT/Word 的大小。
- 图片合成最多 500 页，单页 PNG/JPEG 最多 1600 万像素；任一页失败，整个 PDF 失败，不输出缺页文件。
- 富文本最多 1 MB 的结构文本，所有内嵌图片必须成功读取。导出 HTML 移除脚本、事件属性、主动嵌入和外部样式，并带有限制脚本和外部请求的 CSP。
- 外站媒体、分段流、不能确认来源的资源及无法解析的预览保留明确提示。预览 PDF 不保证包含原 PPT 的隐藏页、动画、备注或可编辑对象。

覆盖包括：

### 原生落盘验收的限制

**真实课程 ZIP 的浏览器原生落盘仍未通过。** 当前已登录的自动化配置在触发下载后使 Chrome 退出；独立进程复核也复现了这个现象。全新无账号配置无法读取目标课程资源，不能用它声称完成了真实课程验证。没有删除账号配置或以其他方式绕过登录。

为验证工具本身输出的内容，验收脚本只在测试页截取新版书签实际生成的 ZIP Blob，再将原样字节写入本机文件并解包校验。上面的 ZIP 结果属于**真实资源／工具输出字节校验**，不是浏览器原生下载成功记录。隔离样本的原生落盘结果与这个限制分别记录。

原始课件、含账号的浏览器配置和本地验收材料均在被 Git 忽略的 `output/playwright/` 下，不进入发布包。
