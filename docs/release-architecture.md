# 当前发布版架构

当前入口是 `web/` 与 `extension/`，共用 `src/runtime/`。首版实现保留用于回归，不再参与当前发布构建。这样可以避免“旧版测试全绿，但部署的是另一份代码”的问题。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `src/runtime/scanner.js` | 课程识别、同源 frame 遍历、目录递归、单元列表、预览元数据与失败汇总 |
| `src/runtime/metadata.js` | 真实文件名与大小解析、原文件入口核对、内嵌预览与仅在线资源识别 |
| `src/runtime/preview.js` | 预览资源声明解析、原格式流／整份 PDF 优先、媒体／图片页／富文本发现；不执行页面脚本 |
| `src/runtime/preview-content.js` | 图片逐页嵌入 PDF、离线富文本 HTML 和 UTF-8 文本生成 |
| `src/runtime/policy.js` | 学校域名、路径、资源 ID 和课程归属校验；安全文件名与 ZIP 重名处理 |
| `src/runtime/network.js` | 会话请求、字符编码、超时与取消、流式体积限制、原文件预检 |
| `src/runtime/response-metadata.js` | 响应文件名解码与比对、MIME／长度／强 ETag 元信息 |
| `src/runtime/file-content.js` | PDF、Office、ZIP 和常见图片的有界结构检查及 CRC；明确区分前缀、结构和未知格式 |
| `src/runtime/archive.js` | 设置规范化、ZIP／逐个下载决策、无压缩 ZIP 生成 |
| `src/runtime/download-queue.js` | 扩展队列持久化、并发名额、Chrome 状态对账、恢复与重试 |
| `extension/background.js` | 面板权限、课程标签页绑定、扫描快照与消息协调 |
| `extension/preview-host.js`、`extension/offscreen.js` | 持有资源流完整校验／预览生成任务和 Blob，串行限制内存，跨面板／Worker 生命周期复用 |
| `extension/content.js` | 顶层 frame 中的扫描协调器及稳定课程标识 |
| `extension/panel.js` | 扩展面板状态、筛选与用户操作 |
| `web/bookmarklet-source.js` | 书签面板、任务生命周期、确认与下载触发 |

UI 不负责构造任意可下载地址。扩展提交 `scanId + ids + requestId`，后台从已保存的扫描快照中查找文件，忽略消息里额外提供的 URL 和文件名。

## 扫描与选择

1. 只接受学校的 HTTP／HTTPS 域名；拒绝相似域名、用户名／密码 URL、重复标识和跨课程链接。
2. 扩展只向顶层 frame 发消息，由同一个协调器检查同源子 frame，避免多个 frame 抢答。
3. 抓取后使用响应的最终 URL 解析相对链接，而不是使用 DOMParser 文档的 `about:blank`。
4. 普通课程导航不作为全部单元范围。实际 THEOL 页面优先使用 `#ul_advance` 学习树，保留折叠的嵌套单元，排除兄弟活动菜单及重复菜单；隐藏的单元清单本身不会决定当前扫描范围。资源壳页面和当前激活的栏目用于区分课程资源与单元学习。
5. 所有普通预览链接都读取元数据，确认原文件名、大小和匹配的下载入口。同一文件在一次扫描中只读取一次；不把标题后缀或 PowerPoint 图标的猜测当作真实后缀。名称清理不调用可能被学校页面改写的 `String.trim()`。
6. 扩展默认一次汇总整门课程，书签同样读取资源目录树和已发现的全部学习单元；不再重复确认扫描范围。读取之前冻结页面与单元清单，后续同课内导航不改变本次汇总范围，扫描仍不自动下载。

单元直接渲染课件预览时，从文件名标题和文件标识识别资源。扫描只读取元数据和预览清单，不下载图片、PDF 或视频正文。原文件入口优先；没有原文件入口时，继续解析预览页声明的原格式资源流、整份 PDF、独立媒体、分页图片和富文本。`downloadKind: original` 加 `downloadSource: preview-stream` 只接受 JSP 声明的同课程／资源 `resPdfShow.do` 流，并保留元数据原名。该接口可能把 Office 原始字节误标为 PDF：仅对这条已校验来源延后 MIME 判断，必须完整验证 Office 类型、目录及 CRC 后用本地 Blob 保存，不把包装页、错误页或错误格式保存为原件。可保存内容用 `downloadKind: preview` 记录来源，只按真实输出格式调整扩展名，不添加“预览版”文件名后缀；原文件大小不用于校验转换副本。无法保存或读取失败的项仍不可勾选，并保留诊断。

目录读取失败会保留错误节点和诊断项；登录失效会中止扫描。资源型课程没有单元内容、或用户主动不读取全部单元时，使用可解释的空状态，不伪造“读取失败”。开始新扫描时先清空选择，失败后不会继续下载旧列表。

扩展为每次扫描保存课程标签页、站点与课程 ID 组成的稳定标识、完整目录树和扫描 ID。后台缓存只保留一份目录树，避免重复存储文件正文和分页清单；入队时从缓存树校验并查找所选文件。相同课程的 URL、hash、可见列表、iframe、目录与单元变化不使快照失效；重新打开面板会复用缓存，范围标签只是本地筛选。真正换课、登录失效、显式刷新替换了扫描 ID 时仍拒绝旧选择。

## 扩展下载队列

状态流转：

```text
queued -> preparing -> downloading -> done
                  \-> failed / cancelled
failed / cancelled -> queued（手动重试）
```

- `preparing` 与 `downloading` 都占用并发名额，最多同时占用 2 个。
- 普通原文件入口及直接可读的预览文件先进行最多 64 KiB 的 Range 预检，核对文件名、MIME、分段范围和已知字节数。小文件若已完整读取，则检查完整结构；大文件仅做前缀检查，不冒充全内容验证。预检记录不保存文件正文。
- 强 ETag 以 `If-Match` 传入原生请求，减少预检与后续下载之间文件版本改变的风险；没有强 ETag 时不能保证两次响应完全相同。
- 队列保存在 `chrome.storage.local`，没有状态变化时不重复写入。扫描快照与课程标签页绑定保存在 `chrome.storage.session`。
- 升级时保留已启动下载的旧保存路径。Service Worker 重启后通过 `chrome.downloads.search` 对账，不能只把内存队列重建为空。
- Chrome 单项状态查询临时失败时保留原下载 ID 和并发名额，其他项仍可对账；不因查询失败取消正在传输的文件。
- 队列存在待处理项时注册约 30 秒一次的 Chrome alarm，关闭面板及 Worker 休眠后仍能重新对账；队列进入终态后清除。新增 `alarms` 权限仅用于本机队列恢复，不连接额外服务器。
- 已开始但无法确认状态的任务标记为需手动恢复，不直接重发，避免重复文件。
- 同一资源的进行中任务去重；重复请求 ID 也去重。已经存在另一项进行中任务时，失败记录不能再次重试该资源。
- 只有 Chrome 报告完成且保存路径、文件名和已知字节数相符时，才显示“浏览器已完成”。接受 Chrome 自动追加的重名序号，并展示实际保存路径；异常落盘文件不自动删除。取消状态来自 `interrupted / USER_CANCELED`，不是不存在的 native `cancelled` 状态。

生成型预览文件和预览页原格式资源流由隐藏的扩展 `offscreen` 文档处理，后台只保存任务 ID、格式、预期大小和临时 Blob 地址，不通过消息复制整份二进制文件。本地准备按任务 ID 复用；Worker 重启后继续使用同一次完整读取／生成的结果。原格式流不是生成型副本，Blob 内保持响应字节不变；校验失败不会创建下载任务。Chrome 返回的 Blob 地址必须与该任务完全一致。结束后撤销 Blob，队列无活动任务时关闭隐藏文档。纯文本和富文本预览的生成源保存在本机队列中，不发送到第三方。

## 书签与 ZIP

书签面板以单实例运行。再次调用只显示已有面板；隐藏不销毁任务；“停止”中止请求；离开页面时清理监听器并取消任务。扫描、下载和设置修改不能相互覆盖。

ZIP 默认上限为 200 MB、120 项；允许设置 10–512 MB、1–500 项。所有打包模式都遵守上限，“优先 ZIP”不代表无限内存。

读取文件时同时检查声明大小与实际流入的字节数，超限就取消 reader；ZIP 头部和目录记录也计入体积预算。跳过失败文件时继续使用已读取的数据，不重新下载此前成功的文件。所有失败时不生成空 ZIP；跳过文件不会占用未使用的重名序号。

原始字节在进入 ZIP 前经过响应文件名、长度和有界内容检查。Office ZIP 检查主文档类型、根关系、本地／中央目录和 CRC；旧 Office 检查复合存储链与根文档流；PDF 检查头部、尾部和交叉引用。检查不改变归档中的原文件。空原始 ZIP、加密 Office 和未能解压校验的条目产生独立内容警示，随预检、归档结果、扩展记录和书签面板传递，不当作传输失败。

路径逐段清理，去除目录穿越、控制字符与 Windows 非法字符；保留合法空格和扩展名。单个路径段同时限制 UTF-16 长度与 UTF-8 字节数，整个相对路径不超过 200 字符；必要时缩短中间目录并加稳定标记。实际可用总路径长度仍受下载根目录与操作系统限制。平铺和保留目录两种模式都处理重名，按大小写不敏感方式比较，避免在 Windows 解压时覆盖文件。

ZIP 上限限制的是包体，不是浏览器的全部内存占用。数据缓冲与 Blob 仍可能产生额外内存占用，因此不把上限提高到数 GB，也不声称是磁盘流式打包。

书签逐个下载复用已完整读取的小文件响应，以 Blob 保存，避免二次 GET 返回不同内容；较大的普通直连文件仍为预检后触发原生下载；预览原格式流始终完整校验并复用字节，逐个下载最多读取 200 MiB。两条路径都只能报告“已触发”，无法查询原生下载完成状态或读取落盘字节。

图片合成最多接受 500 个明确列出的页面，每张 PNG/JPEG 先完成格式及完整性检查；PNG 校验 CRC，单页最多 1600 万像素。逐页按原比例嵌入，任意失败中止整个 PDF；不猜测遗漏页。富文本只保留白名单结构和安全链接，图片内嵌，移除脚本、事件属性、外部样式和主动嵌入内容，并加入禁止脚本／外部资源的 CSP。平台整份 PDF 不走这条生成路径。

## 构建边界

- `npm run build` 构建当前扩展、书签站点及同版本扩展 ZIP；`npm test` 包含发布版测试。
- `scripts/release-extension.mjs` 负责扩展构建；`scripts/package-release.mjs` 用固定时间戳和显式资产白名单打包，官网与单独安装包复用同一实现。`scripts/package.py` 仅保留为兼容入口。
- 站点的版本文案、书签、`downloads/buct-course-downloader.zip` 与 `release.json` 在同一次构建生成；安装包 SHA-256 与大小进入 `release.json`，不依赖手写 Release 下载链接。
- `package.json`、`extension/manifest.json` 和 `src/runtime/version.js` 的当前发布版本必须一致。
- 新版产物位于 `dist/extension/` 和 `dist/site/`。旧版只写入 `dist/legacy-extension/`、`dist/legacy-site/`，其 1.0.1 版本独立校验。
- 构建只清理检查过的本仓库 `dist/` 子目录，拒绝仓库根目录、越界路径和目标符号链接。
- 书签经过完整 URL 编码，防止源码中的 `#` 和 `%` 被 URL 解析破坏；不使用 `eval`、远程脚本或运行时动态导入。
- GitHub Pages 工作流从根锁文件安装依赖，先测试，再构建当前发布版。

## 仍需真实平台验证

自动化覆盖了模拟课程、嵌套 frame、请求失败、取消、下载队列及实际 Chrome 原生／Blob 下载，并逐个对照合成样本的落盘字节。原生传输走隔离的本机回环服务器，而不是仅依赖页面请求拦截。先检查的一门真实课程有 17 个单元、50 条仅预览资源，未尝试猜测下载入口。随后在平台另有明确下载入口的课程中实际下载 PDF、PPTX 和空 ZIP；完整书签界面扫描 76 条课程资源后仅选择一份 PPTX 下载，ZIP 条目与原站原件完全一致。PDF 29 页、PPTX 14 张已用独立文档库打开，原站转换预览的 13 页不能替代原件。2.6.0 随后在原仅预览课程中识别到 22 个预览页声明的原格式流和 28 个预览副本，真实 PPTX／DOCX 及工具生成 ZIP 的字节校验通过；该会话的浏览器原生落盘仍有独立限制，详见 [预览下载验收](preview-downloads.md)。其他课程变体、分页、登录跳转、特殊文件格式及 CSP 行为仍需实际账号会话验收。不要为了“扫描出更多文件”放宽任意域名、任意链接或课程归属限制。

历史实现暂不删除，避免丢失现有回归场景和未提交修复。若以后停止支持首版，应单独归档，而不是让两套构建重新共用同一个输出目录。
