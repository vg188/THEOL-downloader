## 本次修复与回归覆盖

恢复任务后的首次测试为 52 通过、4 失败。保留原有失败用例，并增加相关边界用例后修复：

1. **扫描竞态**：页面检查的等待期间可能出现新扫描。提交和面板刷新现在重新读取最新状态，只使被检查的同一代扫描失效，不返回旧结果或清空新扫描。
2. **URL 缺失**：Chrome 在没有相关站点权限时可能不提供标签页 URL。现在将其判定为不支持的页面，不把 undefined 解析成学校相对 URL，也不尝试注入。
3. **下载入口可用性**：过滤元素及其父级明确 hidden、inert、disabled、ARIA 隐藏/禁用、内联 display:none 或 visibility:hidden/collapse 的入口。
4. **Windows 文件名**：按 UTF-16 长度截断，不切断 emoji 代理对；截断后重新处理末尾点、空格和设备保留名。
5. **文件头校验**：PDF 必须以规范的版本标记开头。网页正文、注释或其他文本中出现 %PDF- 不再被当作 PDF。

6. **原生弹出面板尺寸**：Chrome action popup 通过 `Extensions.loadUnpacked` 和 `chrome.action.openPopup()` 打开，并通过 CDP 目标读取实际原生面板，而不是给普通标签页设置固定 viewport。`html` 根节点提供 440×600 的固有尺寸，`body` 再限制在可用 viewport 内；测试覆盖 1×/1.25× 显示缩放、正常高度和短窗口高度，确认文件列表可滚动、下载页脚和下载记录页均不越界。

7. **GBK 真实平台适配**：实际预览响应为 text/html;charset=gbk。原来的 Response.text() 强制使用 UTF-8，导致 12 个资源均无法识别“文件名”。现改为按响应声明的 charset 使用 TextDecoder 解码，补充 GBK、带引号的 GB2312 和未知编码回归测试。测试仅使用人工生成的中文样例字节，不保存真实 HTML。

其他自动测试覆盖：规范化学校 URL、文件标识匹配、无后缀资源列表、同页去重、预览解析、3 并发扫描、请求与响应体超时、坏 MIME/文件头、2 槽持久队列、重复提交、明确重试、原生取消、后台恢复、可信消息边界、界面选择语义、PNG 图标和最小权限。
