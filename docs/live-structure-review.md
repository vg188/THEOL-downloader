# 2026-10-08 真实 THEOL 页面复核

范围：用户在独立 Chrome 会话中手动登录并指定的一门课程。仅检查页面、HTML 和文件元数据；不提交作业，不修改课程，不请求原文件下载接口。日志和截图仅留在被 Git 忽略的本地目录；本记录不包含账号、Cookie、真实资源 ID 或原始课程页面。

## 发现与修复

| 实际结构／行为 | 原问题 | 2.5.2 处理 |
| --- | --- | --- |
| 同一课程壳包含多组隐藏菜单、重复的学习菜单 | 活动栏目混入，22 个候选项被当作学习单元；资源页误判为单元页 | 优先提取 `#ul_advance` 学习树，实际 17 个单元；用当前资源壳与激活栏目判断页面类型 |
| 学习树有折叠的二至四级目录 | 单纯过滤不可见元素可能漏掉合法嵌套单元 | 保留确定属于学习树的折叠后代，排除其他隐藏栏目组 |
| 平台将 `String.trim()` 改为删除所有普通空格 | 书签版文件名、课程名可能丢失内部空格 | 使用独立的首尾空白清理函数，不依赖被覆盖的方法 |
| 单文件单元直接渲染标题与预览 iframe | 没有普通预览链接的五个 PPT 单元被显示为空白 | 读取内嵌预览的元数据，显示明确的资源状态 |
| 列表标题与原文件名不同，部分页面无下载按钮 | 根据标题后缀跳过验证，可能误认下载能力与文件格式 | 每个普通预览链接都核对元数据和平台提供的匹配下载入口；扫描内去重缓存 |
| 在线视频链接与可供原文件预览的条目混在一个表格 | 仅在线项目被静默忽略 | 显示“仅在线预览”，不抓取视频地址、不猜测下载接口 |
| 资源根目录只有子目录 | “0 个文件”后只留下空树，像扫描失败 | 显示子目录数量，并提示切换“目录树” |
| 扫描已完成但存在不可下载项 | 中性状态仍使用忙碌动画；“仅预览”与请求失败混为一谈 | 分开统计预览项与读取失败项，完成后使用非忙碌提示 |

## 实测结果

- 学习单元：17 个。
- 资源目录：4 个（3 个顶层目录、1 个嵌套目录）。
- 课程资源：23 条；单元资源：27 条；合计 50 条。
- 49 条能读到文件元数据，但页面未提供原文件下载入口；另有 1 条仅在线预览条目。
- 扫描本身无读取失败。只读探测请求的均为课程列表、单元入口、资源列表或预览元数据，原文件下载请求为 0。
- 另打开了一个真实文档预览页复核：仍无下载控件；验证时拦截了转换后的正文加载。
- 新版书签面板可从实际 `javascript:` 书签 URL 启动；搜索能显示此前漏掉的五个内嵌 PPT。
- 50 条只读条目在列表中可见。点击“全选可见”后仍为“已选 0”，下载按钮保持禁用。

这里的“无下载入口”描述的是当前页面实际提供的能力，并不据此断言资源不可查看、课程权限配置有误或用户会话失效。没有通过猜测接口绕过这一边界。

## 尚未覆盖

- 这门课未提供原文件下载按钮，因而没有进行真实原文件下载和落盘验收。原生队列与 ZIP 下载仍由模拟课程的真实 Chrome 回归覆盖。
- 未遇到多页资源目录，不能据此保证其他课程的分页结构已覆盖。
- 未强制退出真实会话测试登录过期，也未检查用户未指定的其他课程。
- 直播、作业、测验、讨论、媒体转换文件不是本轮下载适配范围。

后续若要验证真实下载，需要用户选择一门在平台预览页确实提供“下载”按钮的课程。无需向开发者提供登录密码或 Cookie。
